# 待核验跟踪与业务补值对照（一期）

## 设计与范围
复用原日报引擎：仅在当日日报已完成发送后的原调度窗口内运行一次本地核验，不新增定时任务、消息或@。独立SQLite保存原始版本、计划缺口、检查次数、最新结果、失败原因和不可变的历次观察。按账户、数据日、原报表哈希、计划区分，不修改已发报表、配置和发送账本。

自动登记已发送且回执完整、来源哈希/金额复核通过的新版日报。自动查询最近7个完整自然日；更早记录仍保留为待人工核验，不删除或冒充解决。商品金额按原场景、原日期、计划ID分页查询官方只读接口；直播不支持单计划维度、历史商品映射缺证据时保留原因。空记录与失败不补0；业务补值仍需后续真实值，不当作问题已关闭。实际GMV和消耗均完整时按保存的原政策重新测算，保存原值、新值、差额和观察时间；不会回写原利润或控制预算。原本缺利润时差额保持未知。
