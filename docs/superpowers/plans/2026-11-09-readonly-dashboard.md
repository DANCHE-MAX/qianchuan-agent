# 千川只读决策看板 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 统一日报及影子模型估算口径，增加异常分级与恢复跟踪、七日趋势和投放情景、本机只读查询看板。

**Architecture:** 抽取无网络、无交易动作的利润政策内核，两套运行包部署同一版本。读取已完成日报和已保存事件生成本地看板；新计算使用保存的逐计划政策，旧冻结包及发送账本不改写。异常跟踪使用独立状态库，不以展示层状态取代原发送账本。

**Tech Stack:** Python、Decimal、SQLite、HTML/CSS/原生JavaScript；复用现有图片及Excel工具，无新增付费服务。

**Spec:** 本文“已确认设计”，来自当前会话2026-11-09用户确认。

## 已确认设计

1. 使用已确认分档退款率；无明确档位时用已确认总体率并显著标注。采购倍率3.2，费用合计13.10%，运费不计并注明，达人佣金沿用账户已确认自营口径。参数不是实际账单，利润名称保持预估利润。
2. 数据状态使用“数据齐全、含业务补值、待核验”；单项指标可独立缺失，数据齐全不等于利润准确。
3. 资金不足、持续采集失败、日报发送失败优先；经营异常继续合并。恢复默认随下一次原有提醒呈现，不新增独立群消息。
4. 默认最近7个完整北京时间自然日，商品为主、可展开计划；全店托管独立，未关联计划分别展示。缺失日不补0，历史政策不同不得冒充同口径趋势。
5. 情景输入新增广告费，输出保本需要的新增GMV；提供退款率假设对照，不假设加钱会自动带来同ROI收入。结果不是可执行预算。
6. 本机浏览器看板，按日期、商品、计划筛选，联查日报、影子及异常。复用确定性一问即答，不增加大模型依赖。
7. 既有日报保留原发送顺序，新增细节优先本地展示；暂停反馈，不做周报，不启用任何预算、ROI、计划状态写入。

## Global Constraints

- 修改前备份代码、配置及SQLite一致性副本；记录配置和冻结报表哈希。
- 保留仓库既有未提交修复，不混入本次提交；真实配置、账户映射、数据、群及人员身份不提交GitHub。
- 缺失不得补0，除现有经过复查的零消耗商品计划GMV业务补值规则；直播不套用该规则。
- 已发送历史报表、回执、事件键及账本不改写，不盲目重发、不主动触发生产发送。
- 影子完整运行链包含预算执行路径；验证只调用纯函数和隔离模拟，不能运行完整worker验证新功能。
- 看板仅允许本机访问，不提供发送、改参数、改预算或文件任意读取接口。

## Review Focus

- 商品映射变更或缺少证据：不跨商品合并，未关联计划保留身份。
- 重启/重试：同一异常观察不重复计数，不因没采到数据误判恢复。
- 新旧政策：旧文件不变，新计算逐行绑定政策；同日期多版本不能任意选取。
- 缺失/业务补值：趋势不连成真实零值；状态、排名及情景一致。
- HTML与路径输入：名称转义、目录白名单，无外网暴露及写入路由。
