# 自动利润日报

新版利润报表复用原有 `daily_brief.Engine`，不新增第二个调度器。默认保持旧行为；本地日报配置明确启用 `profit_report` 后，原任务改为发送新版文字摘要、图片和Excel。

## 每日流程

1. 沿用原日报时间与补发窗口（现行规则为北京时间10:00，10:00—12:00重试），数据日期固定为昨日完整自然日。
2. 读取本地账户与已确认季节退款策略。商品、直播及乘方、全域列表分别完整分页，合并日报中的计划ID。仅调用千川只读接口。
3. 商品计划用 `having_cost=NO` 核实无消耗；只有成功且完整的证据才能补广告费0。GMV未返回时，利润和追加额度仍待核验。直播无记录不能按0处理。独立汇总与明细出现矛盾时阻止发送。
4. 按[现行利润规则](current-profit-rules.md)计算，生成图片和Excel。全部无法测算时，汇总显示“待核验”，不显示假零利润。
5. 从原有日报群配置和投手角色配置读取目标与身份，文字消息真实@投手，图片、附件分别发送。反馈处理仍保持暂停，不要求回复或与机器人交互。
6. 全部消息回读成功、@身份验证通过、Excel下载哈希匹配后，才将该账户该日报日期标为发送成功。

## 输出合同

- Excel包含昨日计划汇总、全部计划测算、模型口径与覆盖、缺失与对账。商品/计划名区块盈利绿、亏损红、未知灰。优先显示实际广告费和预估净利润，判断与追加额度放后面。
- 图片采用零基线盈利/亏损柱状图，标注金额。多页使用同一纵轴尺度；未知利润不画成零。计划较多时分页发送。
- 每次输出保存原始接口响应、计算结果、参数版本和采集时间，均仅保留在本地。
- 历史候选追加不是今日预算。报表不调用预算、ROI、计划状态修改接口。

## 发送去重与失败

复用原日报SQLite账本，以账户和数据日期绑定接收群与已准备报表。分段回执保存在该次输出目录。已确认发送的分段重试时不再发送；附件哈希变化时拒绝继续发送。

发送前先持久化尝试记录。网络超时导致结果未知时，不盲目自动重发，需要人工回读核对。已取得消息ID但回读失败时，可重试回读。群、消息类型、@身份、图片标识或附件哈希不一致时，不标记完成。原有日报健康检查继续检查发送完成状态。

## 本地配置和依赖

配置值必须在部署机器单独提供，仓库不附带生产配置：

| 配置来源 | 所需内容 |
|---|---|
| 原有 `.env` | 广告账户及接口授权、飞书应用授权、日报目标群和群白名单 |
| 原有 `rules.json` | `notify.roles` 中的投手身份；原运行模式与其他参数保持原状 |
| 原有 `daily_brief.json` | 保留原时刻和重试窗口，仅显式增加 `profit_report: true` |
| 本地 `profit_daily.json` | 已确认费用比例和广告参考比例；Node、渲染Python和中文字体绝对路径 |
| 本地账户策略 | CONFIRMED季节整体退款率、季节选择、采购倍率及策略版本 |
| `config/feedback.paused` | 继续暂停反馈发布和回复，保留历史反馈账本 |

Excel生成器使用 `@oai/artifact-tool`；图片生成器使用带Pillow的Python。渲染工具路径由本地配置提供，部署时需确保模块可解析、字体可读。上述依赖和 `node_modules` 不随仓库上传。代码不会自动安装依赖、创建账号配置或解除暂停。

## 部署与验证

部署前停止相关本地服务，备份配置、数据、旧输出、被替换程序和服务定义，验证哈希。仅替换清单内的源码，并增加明确授权的日报配置。恢复服务后验证健康、反馈暂停和只读模式。

测试覆盖昨日日期限制、完整分页、直播空记录、零消耗证据、缺失合计、重复执行、重启去重、发送结果未知、回读失败及@缺失。实际发送验证资料只保留在本地，不把群名称、人员标识、真实金额或回执上传GitHub。

回滚只恢复对应源码和日报配置，不用旧数据库覆盖部署后新产生的业务记录。

## 发送修复与新版分析入口

- 千川授权适配器可能直接抛出限流异常。日报读取层对明确的40100/429异常最多尝试3次，两次等待分别为6秒和12秒；其他错误直接上抛，继续由原任务记录失败。失败不会伪造空报表或清空发送账本。
- Excel商品成本先将退款后收入转为整数分，再除采购倍率并按分舍入，与Python Decimal半入舍入一致。生成器继续核对逐行利润、15%情景和汇总；不一致时拒绝发送。
- 本地明确启用`profit_report`后，分析与追问入口读取同一账户、同一数据日期在原发送账本中已完成的新版日报包，不扫描旧`model_*.json`替代。
- “昨日/昨天”严格按`Asia/Shanghai`自然日确定。支持完整年月日及月日；未写年份按北京时间当前年解释，跨年查询请写全日期。默认分析昨日；矛盾日期、多日范围、当日或未来日期不能冒充一个已结束自然日。
- 指定日期未完成、文件损坏、账户或日期不符，返回“待核验”；不改用其他日期或账户。缺失日期也保存为会话范围，追问不会退回之前的成功日报。原旧模式会话不能作为新版事实来源。
- 分析使用日报中保存的`policy`及已计算金额，覆盖旧模型固定费率提示。已确认的0仅作用于对应字段；GMV或利润缺失不能反推已确认的广告消耗也缺失。可计算部分合计不能宣称完整账户利润。
- 本次接入分析与追问入口；原固定“报告/计划”旧模式查询及今日小时查询未迁移。新版解释不要求投手反馈，不执行任何预算、ROI、状态写入。

回归命令：在`agent-runtime`运行`PYTHONPATH=. python tests/run_all.py`。Excel真实渲染回归可通过`QC_TEST_NODE`指定Node可执行文件，并在`tools/node_modules`提供`@oai/artifact-tool`；缺少依赖时该项明确跳过。测试仅使用合成账号、商品、金额与政策，不读取生产配置或原始报表。新增覆盖限流恢复/耗尽/非限流错误、Excel半分舍入、北京时间跨午夜与跨年、错账户、损坏数据、缺失日期、旧会话和缺失后的追问。

## 简洁图片解读与余额提醒

新版日报的普通分析、解读、总结和简短追问默认返回一张手机图片：一句结论、预估净利润/已花广告费、可计算/待核验数量、两个重点计划。金额和结论直接来自准确日期的报表，不依赖LLM重新算数；缺失不补0，合计仅代表可计算部分。重点先选广告消耗最高的可计算计划，再选剩余计划中利润最低者；不足两项按实际数量展示。长名称换行，仍超出时省略，完整名称保留在原Excel。

“详细、全部、逐计划、明细、为什么、原因、对比、比较、表格”等请求保留原文字分析入口。目标日期缺失仍返回待核验文本，不画旧报表。PNG使用现有`profit_daily.json`中的`render_python`与`font`，无需新增生产配置。渲染失败且尚未发送时可简短文字降级；图片上传与原消息回复分开，按入站消息持久化回执，发送结果未知时不盲目重发。图片与回执仅写本地忽略目录，保留日期/账户隔离和原线程回复。

每两小时余额提醒仅展示时间、可用余额、估算时长和充值提示，正文一至两句话。使用现有近两小时余额净下降观测，不等于已核算广告消耗；发送时刻、去重、账户、群和@配置不变。余额不高于原500元参考线时提示充值；估算不足两小时也在文案中提示及时充值，但不改变阈值事件、提醒类别或自动操作。速率为零、过小、采样不全或资金变化时明确无法估算，不宣称可无限投放或暂不需要充值。余额读取失败不使用旧余额替代。

本改动不新增自动调预算、ROI、计划状态操作，不解除反馈暂停。普通日报解读无需LLM；详细问题继续走现有知识分析服务。

## 每两小时余额三时段图片

余额定时提醒改用已确认的横向条状图：蓝色为本两小时，橙色为紧邻的前两小时，紫色为昨日相同北京时间时段。三条使用同一从0开始的横轴，单位元/小时，展示各自时间窗口和速率；保留采样可用余额、按本期速率估算时长及两个变化比例。比较变化按未舍入速率计算，展示再舍入。

时段固定按北京时间整偶数小时结束点定位。每个时段结束点只接受前后5分钟内的同账户样本，再沿用既有两小时计算：起点容差5分钟、连续采样间隔不超过35分钟、实际经过时间作分母。读取29小时历史以覆盖昨日同段；不会用最近一次可用数据替代指定时段。跨午夜和跨年按时区自然日处理。日历查询范围不是累计广告消耗报表，仍为余额净下降观测。

缺少端点、窗口有采样缺口、充值/入账或冻结调整、同一时间数据冲突均保留待核验，不画成0。已核实0速率可显示0，但参照速率为0时变化比例显示“不适用（基准为0）”；未知的比较显示待核验。当前余额读取失败不使用旧余额。全未知图不显示虚假条形或续航。

复用原`balance2h`事件键、群、@配置和发送时刻，不创建第二个调度。图片作为原生卡片图片元素发送，配置的@元素保留；当前低余额事件分类保持不变。队列持久化当次比较视图，重启不会重新拼接其他时段。原有待发卡片不改写，保留全部历史事件与配置。低余额阈值的独立紧急提醒仍保留简短文字。

PNG、渲染输入和发送回执只保存本地。先持久化尝试记录，再发送；结果未知时阻止盲目重发。已取得消息ID但回读失败时仅重读，确认目标群、卡片类型及图片标识后才标已发送。原有30分钟过期事件处理不变。继续使用现有本地`profit_daily.json`的Python和字体，无新增生产配置。缺少渲染配置的旧安装保留原文字模式，不自动创建配置。

测试覆盖三窗口、跨午夜、错账户、缺数/缺点、资金变化、基准0、既有调度去重、图片发送不确定与回读重试。所有测试数据均为合成；本地真实样稿与接口身份不上传GitHub。反馈保持暂停，无预算、ROI、计划状态写入。
