# 现行全账户计划利润估算与输出规则

本页取代此前“三款订单CSV”为唯一来源的说明。旧订单模型保留作为独立核算工具，不与本情景模型混算。生产数据、精确标定退款率、账号和身份配置均不随仓库发布。

## 数据与计算

- 数据取自千川官方只读接口，固定报告日期和账户，不依赖抖店订单或发货数量。
- 计划列表覆盖商品/直播、乘方/全域，并与日报计划ID取并集。列表按total_num、日报按total_number验证完整分页。
- 商品乘方使用OVERALL_ROI_PRODUCT_PROJECT及stat_cost_for_roi2，商品全域使用SITE_PROMOTION_PRODUCT_AD及stat_cost。GMV使用total_pay_order_gmv_include_coupon_for_roi2。保留字段原名及来源。
- 直播主题OVERALL_ROI_LIVE_AWEME不能冒充单计划明细。无计划维度时保留直播级信息，不擅自分摊。空响应不是零。
- 秋冬整体退款率从本地已确认标定配置读取，不在仓库内嵌精确经营参数，不回退到旧季节默认率。
- 预计退款后收入＝GMV×(1−退款率)。商品成本＝预计退款后收入÷采购倍率（现行业务规则为3.2）。其他费用＝预计退款后收入×13.10%。本情景明确不计发货运费，不代表真实运费为0。
- 投前贡献利润＝预计退款后收入−估算商品成本−估算其他费用；预估净利润展示值＝投前贡献利润−实际广告消耗，仍未扣人员、租金等固定费用，不是公司财务净利润。
- 15%广告费＝退款前GMV×15%；15%情景利润单独扣除该广告费，不与实际广告费叠加扣除。
- 历史保本空间＝max(0,实际广告费扣后利润)；历史候选追加＝max(0,min(投前贡献利润,15%广告费)−实际广告费)。不得跨计划挪用亏盈。今天可执行额度一律待核验，不下预算指令。
- 采用Decimal，预计净收入、成本、费用逐项按分四舍五入，再相减。缺失、非有限数、重复日报、跨主题重复及证据矛盾不得静默通过。

## 无明细核查

1. 重新读取无状态筛选的完整日报，并以独立汇总对账，不只重用缓存。按账户、日期、计划ID核对。
2. 商品计划用同日列表having_cost=NO和YES筛选交叉核对，完整分页且成功响应才构成证据。记录请求ID、时间、原始响应路径。
3. 明确命中NO的计划，可以把广告费补0，但这不能证明没有曝光，也不能用当前开关状态证明昨日未投放。
4. 未逐计划返回GMV时保留缺失；即使主题汇总对账一致，也不伪造逐计划收入、利润或追加额度。
5. 直播不支持该筛选。日报/汇总为空或当前LIVE_ROOM_OFF只记为待核验，不填0。
6. 明细合计与独立主题汇总比较；空汇总不能当作对账通过。率限、权限、网络失败单独记录，不能改写成无消耗。

## 输出内容与展示

Excel包含“昨日计划汇总”“全部计划测算”“模型口径与覆盖”和“无明细计划核查”。核查页逐计划显示结论、已核实消耗、证据限制、当前状态及来源；附主题对账差额。汇总说明可测算/缺失覆盖范围。

商品名优先，混合商品计划保留计划名称及文本型计划ID，不能强行映射成一个商品。商品名区块盈利绿色、亏损红色、未知灰色。核心指标先展示已花广告费与“预估净利润”，随后GMV和两种广告情景；投放判断、历史候选追加和今日待核验额度放最后。主展示区不再增加金额状态解释列或三条重复尾注；必要口径放在模型与核查页。

图片与Excel分别输出。图片为以商品/计划名为横轴、昨日预估净利润为纵轴的柱状图，零为基线，盈利绿、亏损红，标注金额。分屏使用同一纵轴刻度；未知值不画成零柱。用简短摘要注明历史日期、覆盖范围和估算属性。

`qc_shadow.plan_profit`实现通用计算、零消耗证据约束和手机HTML表格预览；运行侧的`agent.plan_profit`保持同一算法。原有自动日报现可接入Excel/图片生成及经过回读验证的群发送，见[自动利润日报](automatic-profit-daily.md)。仓库不包含真实工作簿、图片、原始接口响应或群发送回执，克隆仓库不会自动部署或启用任务。

## 消息与反馈

无自动调预算、改ROI、暂停计划。手动报表入口默认本地输出；已授权的自动日报在本地显式启用后，按原任务时刻发群并回读确认图片、附件及@身份。群和投手从本地已有配置读取，不在源码硬编码。

当前暂停要求投手反馈及机器人交互。运行目录存在`config/feedback.paused`时，反馈建议publish与回复处理直接返回，不发催办、不采集反馈；历史账本保留。暂停文件本身不进入仓库。普通报表手动发送不受影响。

## 脱敏发布边界

本仓库只保存通用代码、规则说明和合成测试。真实账号/计划/商品/群/人员ID、名称、路径、精确标定参数、金额、订单、报表、截图、数据库、token及回执不得发布；私有仓库也不例外。本地配置和数据不因GitHub同步而移动、清空或覆盖。

## 日报分析的数据来源与日期约束

新版分析与自动日报共享已完成的报表包，以本地发送账本中的账户和数据日期为索引。“昨日”按北京时间自然日计算；指定日期缺失时明确待核验，不使用旧版模型、较旧日报或其他账户补齐。分析沿用报表保存的政策版本与已计算金额，不重新套用旧固定费率。未知值保持未知，已确认零值只对对应字段有效；仅可计算部分的利润合计不代表完整账户利润。

会话追问沿用本轮明确日期，包括该日尚无数据的情况；旧会话不作为新版数据来源。所有历史候选追加额度仍是历史静态情景，不能直接作为今天的执行预算。反馈暂停和只读边界不变。


## 零消耗GMV业务补值规则（已确认）

仅商品计划（VIDEO_PROM_GOODS）满足以下全部条件时，将缺失GMV按0参与模型计算：同账户、同自然日完整分页的官方无消耗筛选证据确认消耗为0；首次GMV缺失后，按计划ID、相同日期再查询一次官方计划报表；复查成功且分页完整，GMV仍未返回。批量复查按场景和接口限制分组；出现日期、计划范围或消耗矛盾即阻止继续计算。权限失败、超时、分页缺失、无请求证据、消耗未知及直播计划均不得补值。

这是用户确认的业务估算规则，不是平台确认“零消耗必然零成交”。保留`raw_gmv=null`、零消耗证据、复查日期和请求流水；补值行记录`gmv_source=business_rule_zero_spend`及规则版本，标注“业务规则补值”。接口已有GMV（包括真实0或正值）优先，绝不覆盖；后续收到真实值时，新生成报表采用真实值，原冻结包不改写。

导读与本地体检区分可测算数、业务补值数、原始GMV缺失数及剩余待核验数。Excel明细状态及“缺失与对账”页明确标注补值；模型利润随GMV=0计算，但不宣称为已核实经营利润。利润图不为业务补零计划新增零柱分页，注明数量并引导查看Excel，不增加发送消息和@。其他原图表与Excel发送顺序保持，直播仍待核验。

发送前对账核验补值资格与证据，补值不能冒充独立API对账结果；原始API无记录仍保留该事实。仅对新生成报表生效，不重发历史日报。反馈暂停、dry_run和人工投放边界不变，不调整预算、ROI或计划状态。真实数据、配置、身份及回执仅留本地，GitHub只提交脱敏代码、规则和虚构测试。

## 粗略决策辅助一期

导读投放重点与短问答共用 decision_brief：预估正利润降序、负利润升序、已知正消耗降序，各取三项；并列按稳定身份排序。无新出价阈值、无周报、无新增精细对账。缺失不补零，既有零消耗 GMV 业务补值继续保留来源和数量。只用同日同账户商品映射汇总，部分缺失不能用已知利润冒充完整商品利润。全店托管、未关联计划隔离。

新导读 decision_version=1，前置检查按存档版本重建；旧导读保持原版本。原有体检、缺失标识保留。

异常合并只处理新写入 _brief_alert 的规则事件，同账户同类型同窗口最多八项一卡。原事件键、冷却期、准入检查不变。alert_digests 本地账本冻结目标、成员和内容，成功后事务更新成员；传输失败沿用原 UUID，三十分钟过期不补发，不清空旧账本。退款和余额事件维持原流程。没有确定商品映射时保留计划名称及身份，不猜测合并商品。

短问答先精确读取日期，命中问题后确定性排序，仅用户主动查询才回复。保持原附件顺序和一次 @，不改变反馈暂停与 dry_run，不上传配置、真实数据、群和人员信息。

## 异常提醒ROI显示规则

- 仅调整异常提醒的ROI文本格式，不修改指标来源、计算结果、异常阈值或投放策略。
- 已知ROI固定显示两位小数，例如原始 `0E+2`、字符串 `0` 和数值 `0` 均显示 `0.00`；不使用科学计数法。
- 缺失ROI（`None`）显示“暂无”，不得填成0；真实0不得误判为缺失。
- 对新生成提醒生效；已发送消息和冻结发送账本保持原样，不为显示修复重发。
- 回归测试仅使用虚构计划，覆盖科学计数零、字符串零、数值零、缺失值和普通小数。配置、真实数据、群和人员信息只留本地。
- 继续暂停反馈，保持dry_run，不自动调整预算、ROI或计划状态。

### 异常回调去重与采集恢复

- 异常卡ROI显示为“区间观测ROI”：对应快照增量比值，不冒充当日累计ROI、真实订单时段或财务利润。
- 指标回调按账户、计划、指标、原始快照区间及前后值形成持久事实键，与数据可比状态变化分开。首次迁移关联历史已发送及未确认发送记录，避免升级后重报；不同计划或区间的新回调正常登记。已发历史消息和发送账本保留。
- 千川读取使用本运行目录内按应用共享的跨进程请求门控：正常完成后至少间隔0.8秒；遇40100等暂时错误共享5/10/20/40/60秒冷却并加随机抖动；网络异常共享5/10/20/30秒冷却。此为本地保守节奏，不代表平台公布额度，也不涵盖其他运行目录的客户端。
- 本地诊断记录每次尝试序号、接口类别及DNS/超时/TLS/连接错误分类；不输出凭证、请求参数、身份或异常原文。持续故障仍按原机制提示，不以零值替代失败、不屏蔽凌晨真实异常。
- 电脑Wi-Fi/AP的定时重启或换信道需网络管理员核对；本模块不修改路由器、无线网络或系统代理设置。
- 反馈继续暂停，保持dry_run，不自动调整预算、ROI或计划状态，不发送测试群消息。

## 只读看板与统一模型（2026-11-09）

- 新生成日报及ROI影子分析使用 `unified-readonly-v1`：已确认分档退款率；未明确映射时使用已确认总体率并标注回退。采购倍率3.2、费用13.10%，运费excluded。仍为模型投后贡献利润，不是实际结算净利润。
- `data/model_policy/authority.json` 是本地账户授权映射，不入Git。两个运行目录指向同一份依据。每份新报告保存政策版本、逐行政策和来源；成本先按分取整，两个只读模型使用同一实现。
- 旧报表、发送回执、事件键不改写。旧政策与新政策切换时，前日利润比较待核验；既有金额冲突、账户/日期冲突继续阻止发送。体检同时校验逐行政策绑定及Excel退款率。
- 旧预算执行链的模型与准入不在本次修改范围；新看板和ROI分析不调用执行器，不触发预算、ROI、启停变更。
- 数据状态为“数据齐全/含业务补值/待核验”，仅描述输入完整程度。直播缺失不补0；无数据日不补0；已知部分单独注明范围，不冒充全账户合计。
- 近7日按北京时间完整自然日展示。商品映射须同账户同日明确，全店托管独立，未关联计划单列。商品某指标部分缺失，该指标合计待核验。
- 新增广告情景：所需新增GMV = 新增广告费 / [(1-退款率)×(1-1/3.2-13.10%)]，向上取分。该情景仅覆盖新增广告费，不弥补已有亏损，不预测收入；对照退款率不写回生产参数，不是统计置信区间。
- 异常生命周期独立落库 `data/qianchuan/alert_lifecycle.db`。资金及日报发送失败优先，连续两个独立采集窗口失败升级。缺失观测不算恢复；同观察窗口不重复计数，旧观察不覆盖新状态。规则异常只有完整可比窗口且对象仍存在才可恢复。
- 恢复内容仅附在后续原余额/合并异常通知中，无原通知时仅留本地。附加内容随原消息冻结，发送成功后确认；不新增独立群消息，不绕过原去重及冷却。
- 本机看板固定127.0.0.1，只支持白名单GET/HEAD，拒绝POST/PUT/DELETE、外部Host/Origin及任意文件路径。读取完成账本和哈希验证的日报/附件，缺日期不使用旧报告替代。
- 反馈保持暂停；日报原顺序、一次@及凌晨不单发两日图规则不变。不做周报。
