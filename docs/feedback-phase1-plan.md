# 投手反馈闭环 Implementation Plan

**Goal:** 完成已确认的第一期反馈记录、只读核验和CSV导入修复。
**Architecture:** 独立SQLite账本保存不可变建议与事件；消息监听分流到反馈模块；复用现有预算GET适配器，和预算写操作隔离。
**Tech Stack:** Python、SQLite、既有飞书通知器/千川预算读取模块。
**Spec:** [设计](feedback-phase1.md)

## Global Constraints
- 不自动调整预算，不改生产配置和数据；测试临时库，默认不发送。
- 凭据、身份、原始业务数据不得提交GitHub。

## Review Focus
- 跨群/跨账户/非投手/错误引用/机器人消息拒绝。
- 重复消息、乱序修订、核验中反馈变化不得错配。
- 预算类型错配、数据缺失/过期、NaN不得标为已核验。
- 发送超时和重复发送不得重复创建群通知。
- CSV部分更新和未知编号不得丢失历史或虚报计数。

## Tasks
- [x] CSV：先写部分更新、未匹配、无效金额、审计测试；修复store和CLI，验证。
- [x] 账本：先测试建议去重、不可变事件、绑定、查询及核验边界；实现feedback_store与feedback。
- [x] 群入口/CLI：测试真实分流、API回读身份、缺失配置、发送不确定与复盘；实现无写预算路径。
- [x] 全量测试、敏感扫描、原配置哈希检查、更新说明并推送GitHub。
