# 投手反馈闭环第一期

目标：复用配置的飞书目标群、投手角色及当前广告账户，建议编号→投手反馈→自报执行→只读预算核验→查询复盘。所有平台操作仅使用现有预算读取接口；不接入预算审批执行链路、不自动修改预算、不新增自动群提醒。

新增独立 `data/feedback_loop.db`，原 `app.db` 不迁移、不写入，除非用户显式运行旧CSV导入命令。建议保留款号、计划、数据截止、模型版本、缺失项、目标预算类型与数值。金额缺失保持null；历史剩余额度不能作为日预算。建议与数据快照均按24小时有效（取较早截止时间），过期仅能查询、拒绝/暂缓或记录执行事实，不能重新批准为可投额度。

群内命令：`反馈 编号 采纳`、`反馈 编号 修改后采纳 金额 原因`、`反馈 编号 暂缓 原因`、`反馈 编号 拒绝 原因`、`反馈 编号 已执行 金额 ISO时间 原因`、`核验反馈 编号`、`反馈详情 编号`、`反馈列表`。变更反馈必须引用对应建议原消息并@机器人；从飞书API回读消息验证身份、群、引用及时间。记录所有反馈修订与消息去重。

只读核验：核对当前账户/计划/预算类型/金额/快照时效，与最新自报执行比较，输出一致、不一致、待核验。只说明当前设置是否相符，不证明谁操作，也不等于真实消耗或保本保证。未确认计划映射、预算类型或缺失执行金额时不调用接口。历史建议数据缺失仍显式展示。

本期提供手动查询复盘和缺失清单；2h/24h经营效果与最终利润缺少同口径证据时显示待补，不自动推断因果或生成可投额度。后续自动效果回收及定时催办不在本期启用。

建议从本地JSON显式登记；CLI默认只登记/预览，`send --id 编号`才向配置群发送并@投手。发送前持久化不确定标记，成功绑定飞书消息ID；失败/超时不自动重发。没有发送回执的建议不能接收群内变更反馈。

CSV修复：只统计实际更新行，报告未匹配、无效、无变化明细；空白/缺省字段不覆盖旧值；无效数字和非法状态拒绝，保留修改审计。

开发与测试仅操作独立仓库、临时目录和模拟接口，不读取真实密钥、不发送群消息、不修改生产配置或数据库。本期交付GitHub代码，不自动部署到本机服务。

## 使用方式

本期代码未自动部署到生产；不要把脱敏仓库中的示例退款率和账号覆盖到运行目录。后续部署只迁移功能源码，保留原配置与数据库。

在运行目录中准备一个本地JSON（不能提交GitHub），字段如下。金额是明确的日预算/总预算设置值，**不是**历史可追加广告费，也不是已花广告费：

```json
{
  "style": "DEMO",
  "plan_id": "123",
  "snapshot_at": "2026-11-05T16:00:00+08:00",
  "model_version": "reviewed-v1",
  "budget_mode": "BUDGET_MODE_DAY",
  "target_budget": "100.00",
  "missing": [],
  "revision": "1"
}
```

- 所有示例均为合成值；必须填写实际数据截止时间与缺失清单。目标预算缺失填`null`，不填0。
- 相同内容和revision重复登记返回原编号，不延长有效期；更新数据后重新登记，或在确认后修改revision。
- 群、投手和账户从现有 `.env` / `rules.json` 加载，不接受输入JSON另行指定收件群或身份。
- 本期需显式登记建议，不自动把历史利润报告中的剩余额度转换成计划日预算。

```sh
python tools/feedback_loop.py create --file /path/to/local-suggestion.json
# 上一步仅登记/预览；得到FB-...编号后，如确定发送：
python tools/feedback_loop.py send --id FB-编号
python tools/feedback_loop.py show --id FB-编号
python tools/feedback_loop.py verify --id FB-编号
python tools/feedback_loop.py list
```

实际编号格式为`FB-`加20位十六进制字符。`send`是唯一主动发送建议的命令；反馈查询由投手在原群@机器人触发。发送超时会停在uncertain，必须人工核对，不会重发。没有发送成功回执的建议不接受群内变更反馈。

投手引用建议并@机器人：

```text
反馈 FB-实际编号 采纳
反馈 FB-实际编号 修改后采纳 120 更换素材后小额测试
反馈 FB-实际编号 暂缓 等素材
反馈 FB-实际编号 拒绝 库存不足
反馈 FB-实际编号 已执行 120 2026-11-05T16:10:00+08:00 手动修改日预算
```

查询可以不引用消息，但必须是配置群内的投手：`反馈列表`、`反馈详情 FB-实际编号`、`核验反馈 FB-实际编号`、`反馈帮助`。

预算核验结果只指读取时的设置；查看旧结果会展示核验时间，需要最新情况时再次发起只读核验。自报执行不是审批，不会调用预算写入模块。2h/24h效果回收与自动催办尚未启用。

CSV仍使用`python main.py feedback --file /path/to/feedback.csv`。返回updated/unmatched/invalid/unchanged数量和逐行明细；空白不清空旧值；有未匹配或非法行返回非零退出码。旧CSV反馈写入原decision表并增加审计，新群内闭环独立存储，二者不会隐式互相覆盖。
